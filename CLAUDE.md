## Project overview

Firmware for a hardware audiometer built on an Arduino Nano ESP32 (PlatformIO, Arduino framework, `espressif32` platform, `arduino_nano_esp32` board). It generates pure tones through an I2S DAC, controls stimulus loudness through a PT2258 I2C attenuator, drives a small SPI TFT for the operator UI, and runs a semi-automatic Hughson-Westlake threshold-hunting protocol using physical buttons (clinician controls + patient response button).

Code comments and log strings are in Polish; keep new comments consistent with that unless the user asks otherwise.

## Build / common commands

This is a standard PlatformIO project (no custom build scripts). Use the PlatformIO CLI:

pio run -t clean        # clean build artifacts (.pio/build)

## Architecture

All firmware source lives flat in `src/` (no subdirectories). Each module pairs a `.h` (public API + brief doc comments) with a `.cpp`:

- **`types.h`** — the shared data model: `DeviceState` (main state machine states), `AudiometerData` (current ear/frequency/intensity/response state, passed as `volatile` pointer across modules since it's touched from ISR-adjacent code), `MenuNavigation` (reserved, unused), the `freqTable`/`toSendResponses` externs, and audio constants (`SAMPLE_RATE`, `TABLE_SIZE`, `BUFFER_SIZE`). Treat this as the cross-module contract.
- **`pins.h`** — single source of truth for all pin assignments (I2S DAC, I2C/PT2258, buttons, TFT SPI). Note the commented-out encoder pin block: those pins are **not yet wired** and currently collide with I2C/I2S pins already in use — any future encoder support must pick different pins first.
- **`main.cpp`** — owns the top-level `DeviceState` state machine (`STATE_POWER_ON → STATE_SELF_TEST → STATE_SELECT_MODE → {STATE_SEMI_TEST | STATE_MANUAL_TEST} → STATE_FINISHED → …`) in `setup()`/`loop()`. Initialization order matters and is intentional: `display_init()` runs before I2S/I2C (kept that way to diagnose a white-screen issue), and the DAC's `XSMT_PIN` is only driven high (un-muting the DAC) after all peripherals are configured.
  - `STATE_SEMI_TEST` implements the full semi-automatic clinical loop: iterates both ears × `freqTable`, runs up to 3 measurements per frequency applying the audiometry "2-of-3 agreement" rule (re-measuring indefinitely until two results agree), and stores results into `toSendResponses[freq][trial][ear]`.
  - `STATE_MANUAL_TEST` is a stub — display screens for it (`SCREEN_5`..`SCREEN_9` in `display.h`) exist, but the manual-mode measurement protocol itself is unimplemented (see TODO in `main.cpp`).
- **`protocol.cpp`/`.h`** — `protocol_hughsonWestlake()` is the core threshold-hunting algorithm (descend in -10 dB steps on patient response, then ascend in +5 dB steps until response, per standard Hughson-Westlake methodology), driven by an `IntensityChangedCallback` so the UI can live-update during the procedure. Also owns `freqTable` (the 8 test frequencies, note 1000 Hz is tested twice per convention) and `protocol_sendDataToPC()` (dumps full results over Serial for a PC-side receiver).
- **`audio.cpp`/`.h`** — I2S driver setup and sine-wave tone generation (`ESP-IDF driver/i2s.h`, not the Arduino `I2S` library). Steers stereo output hard-left/hard-right based on `currentEar` (mono tone duplicated to the active channel, silence on the other).
- **`volume.cpp`/`.h`** — PT2258 volume-control chip over I2C (`Wire`). Works in dB HL (0–70) internally, converts to the chip's attenuation encoding (70 − targetDb, clamped 0–79) and writes it to all 6 channels' worth of registers (only channels 1–2 are actually used for L/R here).
- **`buttons.cpp`/`.h`** — 4 physical buttons (right/down/OK/patient-response) wired as `INPUT_PULLUP` + `FALLING` interrupts, each with a 250ms software debounce inside the ISR. Sets `volatile bool` flags that `main.cpp`/`protocol.cpp` poll and manually clear after handling — there is no queue, so a flag can be missed if not cleared/checked promptly.
- **`display.cpp`/`.h`** — bit-banged SPI driver (manual `writeCmd`/`writeData`, no external TFT library) for a small display, plus a built-in 5×7 bitmap font renderer and a simple screen-state UI (`ScreenState` enum, `display_showScreen()` for full redraw, `display_render()` for the current screen's live-updating fields). UI conventions **intentionally differ** from internal logic conventions in a couple of places — most importantly the ear convention: display/UI uses `0=Prawe(Right), 1=Lewe(Left)` while `AudiometerData.currentEar` uses `0=Lewe(Left), 1=Prawe(Right)`. The conversion happens explicitly at the `STATE_SELECT_MODE → STATE_SEMI_TEST` transition in `main.cpp` — be careful not to break this inversion when touching either side.

### Data flow summary

`buttons` (ISR flags) → `main.cpp` state machine → `protocol_hughsonWestlake()` (reads button flags, calls `audio_generateTone()` + `volume_setDb()`/`volume_quiet10db()`/`volume_louder5db()`, invokes the intensity-changed callback → `display_setIntensity()` + `display_render()`) → results collected into `toSendResponses` → `protocol_sendDataToPC()` prints them over Serial at the end of a run.

### Known gaps / in-progress areas

- `STATE_SELF_TEST` is a no-op placeholder (real hardware self-test not yet implemented).
- Manual test mode (`STATE_MANUAL_TEST`) has display screens but no protocol logic.
- Encoder support is planned but unwired; pin conflicts must be resolved first (see `pins.h`).
- `src.zip` at the repo root appears to be a manual backup snapshot, not a build artifact — leave it alone unless asked.
